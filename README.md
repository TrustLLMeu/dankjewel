## Online Evaluation System for LLM-Generated Text

A modular, multi-dimensional evaluation framework based on the TrustLLM project protocol (D7_5) for assessing the quality of text generated by Large Language Models.

### Architecture Overview

The system is built on a **four-pronged evaluation approach**, each analyzing different aspects of generated text:

- **Prong 1: LLM-as-Judge** - Uses neural embeddings and lightweight models (vLLM skeleton)
- **Prong 2: Rule-Based** - Lexicon and pattern-based metrics (FULLY IMPLEMENTED)
- **Prong 3: Extraction-Based** - Claim extraction and fact-checking (skeleton)
- **Prong 4: Intrinsic** - Model-internal metrics like perplexity and entropy (skeleton)

### Quick Start

#### Basic Usage

```python
from src.pipeline import EvaluationPipeline

# Initialize pipeline with specific prongs (1=LLM, 2=Rule, 3=Extract, 4=Intrinsic)
pipeline = EvaluationPipeline(enable_prongs=[2])  # Start with rule-based

# Evaluate text
text = "Dear Madam, I would like your help. Thank you for your time."
result = pipeline.evaluate(text)

# Print JSON output
print(result['aggregated_scores'])
```

#### Run Full Example

```bash
python3 main.py
```

This evaluates 4 example texts across all prongs and outputs JSON results.

### Evaluation Dimensions

#### Prong 2: Rule-Based (✅ Fully Implemented)

| Dimension | Method | Range | Description |
|-----------|--------|-------|-------------|
| **Fluency** | Flesch Reading Ease | 0-1 | Text readability and complexity |
| **Politeness** | Lexical cues | 0-1 | Polite vs. rude language markers |
| **Emotional Intensity** | VADER + punctuation | 0-1 | Emotional expression strength |
| **Formality** | Formal/informal markers | 0-1 | Formal vs. casual language |
| **Hedging** | Modal verbs & cues | 0-1 | Uncertainty and speculation level |

#### Prong 1: LLM-as-Judge (⏳ Skeleton - vLLM Ready)

Planned dimensions:
- Relevance (semantic similarity to prompt)
- Semantic Coherence (sentence-level coherence)
- Reliability (topic stability)

#### Prong 3: Extraction-Based (⏳ Skeleton - spaCy Ready)

Planned dimensions:
- Factual Accuracy (offline Wikidata verification)
- Factual Consistency (internal contradiction detection)
- Temporal Accuracy (time anchor extraction)
- Comparative Factuality (superlatives/comparatives)
- Modality Awareness (hedged vs. strong claims)

#### Prong 4: Intrinsic (⏳ Skeleton - Logits Ready)

Planned dimensions:
- Uncertainty (mean token confidence)
- Perplexity (text predictability)
- Entropy (token distribution entropy)

### Score Aggregation

Scores are aggregated using a **weighted average formula**:

```
M = w₁S₁ + w₂S₂ + w₃S₃ + w₄S₄
```

Where:
- S₁, S₂, S₃, S₄ are prong scores (average of their dimensions)
- w₁, w₂, w₃, w₄ are configurable weights (default: 0.25 each)
- All scores are normalized to [0, 1] range

### Performance Notes

- **Current latency**: ~1 second for Prong 2 evaluation (textstat is the bottleneck)
- **Target latency**: <3 seconds total for all prongs
- **Memory usage**: Minimal (~50MB) without pretrained models
- **Scalability**: Fully parallelizable across prongs

### Design Principles

1. **Modularity**: Each dimension and prong is independent
2. **Flexibility**: Prongs can be enabled/disabled per use case
3. **Explainability**: All scores include raw values and metadata
4. **Language-agnostic**: Some metrics (intrinsic, Wikidata) work across languages
5. **Graceful degradation**: Missing prongs don't crash the system
